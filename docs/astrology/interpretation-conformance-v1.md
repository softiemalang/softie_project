# Astrology interpretation conformance v1

`astrology-interpretation-conformance-v1` checks a machine-readable downstream candidate against the frozen handoff and read protocol. It is a conformance gate, not an interpretation evaluator: it does not read free-form meaning, score warmth or accuracy, generate text, rank claims, or decide which claim is true for a person.

The candidate contains only upstream claim references (`claimPath`, exact `claimType`/`value`/`epistemic`/`sourceRefs`), an explicit `all_upstream_claims` coverage declaration, and restricted assertion metadata. Every used claim must match the graph node byte-for-byte at the structured-value level. Structural graph relations may use only the frozen vocabulary and `structural_co_occurrence_only`; orb, phase, motion, and rule identity cannot become life-importance or meaning weight. Experience-dependent precedence, unsupported psychology/destiny, promotion, simulation/Placidus/frozen-speed/legacy-Prep contamination, and prompt/LLM/API traces fail closed with stable violation codes.

The output records `conformant` or `non_conformant`, requirement and violation locations, claim/source references, input identities, protocol/candidate content hashes, and the unchanged boundary: local research eligible, user delivery blocked, production activation blocked, human review required, `availableForInterpretation:false`, `connected:false`, `not_connected`, and `interpretation_packet_not_activated`.

Materialize and independently check:

```sh
node scripts/materialize-astrology-interpretation-conformance-v1.mjs
node scripts/check-astrology-interpretation-conformance-v1.mjs
```

The candidate fixture is deterministic and machine-readable. Negative evidence is generated by explicit structured mutations; no LLM, API, prompt, UI, DB, activation, or production path is invoked.
